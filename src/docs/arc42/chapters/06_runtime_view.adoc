[[section-runtime-view]]
== Laufzeitsicht: Der Build erledigt die Arbeit, im Browser trägt das Kind jede Information

Zwei Laufzeiten gibt es: den Build auf dem Rechner der Autor:in oder in GitHub Actions und den Browser
des Kindes. Kein Szenario hat einen Server der Apps als Beteiligten. Wo App und Tutor Daten
austauschen, trägt das Kind sie: als Link, als Aufgabennummer oder als Ergebniszeile. Die Tabelle am
Ende zeigt, welcher Baustein aus xref:05_building_block_view.adoc#section-building-block-view[Kapitel 5]
in welchem Szenario vorkommt.

[[section-rt-build]]
=== Szenario 1: Der Build macht aus App-Ordnern eine geprüfte Site

[plantuml, target=laufzeit-build, format=svg]
....
@startuml
autonumber
actor "App-Autor:in / CI" as autor
participant "Build\n(eleventy.config.js)" as cfg
participant "Build\n(lib/apps.js)" as apps
participant "Apps\n(src/<app>/)" as app
participant "Mathe-Karte\n(lib/karte, src/karte)" as karte
participant "Layout\n(src/_includes, *.njk)" as layout
participant "Build\n(lib/bild.js)" as bild
participant "Kern\n(svg.js, zufall.js)" as kern
participant "Build\n(pruefungen, versionierung)" as nach

autor -> cfg : npm run build
cfg -> apps : ladeApps({ quelle: "src", adressen: site })
apps -> app : import js/app.config.js (je Ordner)
apps --> cfg : apps[] mit basisUrl, farbe, kompetenzen[nr]
cfg -> karte : karte.11tydata.js → ladeKarte(apps)
karte --> cfg : Knoten, Einträge aus kartenEintrag/kartenKnoten
cfg -> layout : rendert Übersicht, je App start/test/manifest, je <id>.md kompetenz.njk
layout -> bild : {% bild app.pfad, k, bild %}
bild -> app : erzeugeAufgabe(erzeugeZufall(seed)), zeichne…(svg, aufgabe)
bild -> kern : leeresSvg, svgEl (Mini-DOM), alsSvgText
bild --> layout : <svg …> statisch in der Seite
cfg -> nach : eleventy.after: pruefe(apps, _site)
alt mindestens ein Regelverstoß
  nach --> autor : "Build-Prüfung: n Fehler" – Exit-Code ≠ 0
else alles gut
  nach -> nach : versionsHash(JS/CSS/JSON) → versioniere(HTML, JS)
  nach --> autor : "[lern-apps] 3 App(s) geprüft, ?v=8cb344d1"
end
@enduml
....

Gemessen am 23.09.2026: 45 Seiten, 103 kopierte Dateien, Eleventy meldet 0,41 s (Konsolenausgabe
von `npm run build`).

[[section-rt-aufgabe]]
=== Szenario 2: Der Tutor verlinkt eine Aufgabe, das Kind löst sie

Claude schickt „Mach Aufgabe Nr. 42“ mit einem Link wie
`https://lernapps.github.io/binom/erste-binomische.html?seed=42`. Das Kind öffnet ihn, rechnet auf
Papier und tippt das Ergebnis. Das Ergebnis prüft die App. Ein Foto des Rechenwegs prüft der Tutor
erst, wenn die Kompetenz in die Klassenarbeit-Phase kommt, eines je Kompetenz
(xref:09_architecture_decisions.adoc#adr-022[ADR-022]).

[plantuml, target=laufzeit-aufgabe, format=svg]
....
@startuml
autonumber
actor "Lernende" as kind
participant "Layout\n(erzeugte Seite)" as seite
participant "Kern: Seitenstart\n(seite.js)" as start
participant "Kern: Zufall /\nAufgabenlink" as zufall
participant "Kern: Trainer\n(ui.js)" as trainer
participant "Apps\n(aufgaben/<id>.js, vis/<id>.js)" as app
participant "Kern: Zahlen und Terme,\nPrüfergebnis" as zahlen
participant "claude.ai" as claude

kind -> seite : öffnet Link mit seed=42
note right of seite : Text und Bild sind schon da (statisch)
seite -> start : starteSeite({ app: APP, modul, visualisiere })
start -> zufall : leseSeed → 42; leseVorgaben(query, URL_ZAHLEN, URL_TEXTE)
start -> trainer : starteTrainer({ seed: 42, vorgaben })
trainer -> app : erzeugeAufgabe(erzeugeZufall(42), vorgaben)
trainer -> app : zeichne…(svg, aufgabe) – dieselbe Funktion wie im Build
kind -> kind : rechnet auf Papier, Aufgabe und Rechenweg
kind -> trainer : tippt Antwort, "Prüfen"
trainer -> app : pruefeAntwort(aufgabe, antworten)
app -> zahlen : pruefeTermAntwort / pruefeZahlAntwort
zahlen --> trainer : { korrekt, fehler, felder, meldung }
trainer -> kind : Meldung (richtig / Hinweis neutral / falsch), Zähler
kind -> claude : nur in der Klassenarbeit-Phase: Foto des Blatts mit Aufgabe und Rechenweg (nicht über die App)
claude -> kind : erster falscher Schritt als Leitfrage – oder "Weg stimmt"
note over seite, zahlen : Die App sieht den Rechenweg nie (ADR-022)
@enduml
....

[[section-rt-fehler]]
=== Szenario 6: Fehler und Wiederherstellung: Der Build hält an, der Browser fällt zurück

Fehler im Build halten die Auslieferung an, bevor ein Kind sie sieht. Fehler im Browser enden in einem
Rückfall, den das Kind sieht und selbst auflösen kann.

[plantuml, target=laufzeit-fehler, format=svg]
....
@startuml
autonumber
actor "App-Autor:in" as autor
participant "Build\n(lib/karte, lib/pruefungen)" as build
participant "Mathe-Karte\n(Daten)" as karte
actor "Lernende" as kind
participant "Layout\n(alte, gecachte Seite)" as seite
participant "Kern" as kern
participant "Browser-Speicher" as ls
participant "GitHub Pages" as pages

group Unbekannter Karten-Knoten
  autor -> build : kartenKnoten: ["gibt-es-nicht"] in app.config.js
  build -> karte : Knoten-ids aus src/karte/daten/kompetenzen/
  build --> autor : "Mathe-Karte: Datenprüfung fehlgeschlagen: … ist kein Knoten der Karte" – Build rot
  autor -> build : id korrigiert → Build grün
end
group Cache nach einem Deployment
  kind -> seite : HTML bis zu 10 min alt aus dem Browser-Cache
  seite -> pages : GET kern/js/seite.js?v=<alter Hash>
  pages --> seite : Datei der neuen Version (Pages ignoriert die Query)
  note right of seite : Einzelfall R-013; neu laden holt die neue Seite,\nderen URLs tragen den neuen Hash
  kind -> seite : neu laden → alle URLs ?v=<neuer Hash>
end
group localStorage gesperrt
  kern -> ls : setItem
  ls --> kern : Exception
  kern -> kind : "Konnte … nicht speichern. Kopier dir die Zeile."
end
group Ungültige URL-Parameter
  kind -> kern : …?seed=abc&wert=-5
  kern -> kind : Zufallsaufgabe mit neuer Aufgabennummer 1–9999
end
@enduml
....

[cols="2,4",options="header"]
|===
| Fehlerfall | Verhalten und Quelle
| Unbekannter Karten-Knoten | `pruefeAppEintrag` meldet Datei und Knoten; `ladeKarte` wirft, der Build bricht ab (`lib/karte/eintraege.js:46`, `lib/karte/laden.js:53-56`). Auch ein Übergangseintrag für eine App, die ihren Eintrag schon selbst trägt, bricht ab (`lib/karte/eintraege.js:57-59`).
| Regelverstoß im Build | Externe Ressource, Datei über 500 Zeilen, fehlende Kompetenz-Datei, Seite fehlt in `llms.txt`: `eleventy.config.js` wirft mit allen Funden; nichts wird deployt.
| Unbekanntes Fach, falsche App-Konfiguration | `fachfarbe` wirft (`lib/fachfarben.js:29-32`); `pruefeAppKonfig` meldet fehlende `id`, `titel` oder falschen `pfad` (`lib/apps.js:12-18`).
| Cache nach Deployment | Neue Seiten fordern nur URLs mit neuem Hash an (xref:08_concepts.adoc#section-auslieferung[8.10]). Nur eine alte, gecachte HTML-Seite kann für einen Aufruf alte und neue Module mischen (xref:11_technical_risks.adoc#r-013[R-013]); neu laden behebt es.
| Doku-Build scheitert | `pages.yml` bricht ab, bevor das Artefakt entsteht; die zuletzt deployte Fassung bleibt online (xref:11_technical_risks.adoc#r-011[R-011]).
| `localStorage` gesperrt oder voll | Alle Zugriffe in `try/catch`; Laden liefert einen leeren Wert, Speichern `false`; die Seite sagt es dem Kind (`src/kern/js/storage.js:17-21`).
| Ungültige oder fehlende URL-Parameter | `leseSeed` akzeptiert nur Ziffern, sonst Zufallsnummer (`src/kern/js/zufall.js:47`); `leseVorgaben` übernimmt nur gültige Werte; `leseModus` fällt auf `voll` zurück (`src/kern/js/testablauf.js:15-18`).
| Zwischenablage verweigert | `kopiereText` markiert den Text (`src/kern/js/aufgabenlink.js`). „Zurück zu Claude“ lässt den Tab dann offen und zeigt die Zeile markiert in einem Feld (`src/kern/js/zurueck.js`, Szenario 7).
| Tab lässt sich nicht schließen | Nach `window.close()` prüft „Zurück zu Claude“ nach 300 ms `window.closed` und sagt dem Kind per `aria-live`, dass es den Tab selbst schließen soll (xref:09_architecture_decisions.adoc#adr-021[ADR-021], Szenario 7).
| claude.ai kann `tutor.md` nicht laden | Außerhalb des Systems. Rückfall: TalkItOver-Provider „copy“ kopiert den Prompt; `llms.txt` ist auf der Startseite verlinkt (xref:11_technical_risks.adoc#r-002[R-002]).
|===

[[section-rt-zurueck]]
=== Szenario 7: Tutor-Deep-Link → Übung → Zurück zu Claude

Claude schickt „Mach Aufgabe Nr. 4“ mit
`https://lernapps.github.io/binom/erste-binomische.html?nr=4&von=tutor`; claude.ai öffnet ihn in einem
neuen Tab. Nach der Aufgabe bringt ein Knopf das Kind samt Ergebnis zurück in den Chat
(xref:09_architecture_decisions.adoc#adr-021[ADR-021]). Die Ergebniszeile geht nur in die Zwischenablage
des Geräts. Der Test verläuft genauso: Der Knopf steht neben der Ergebniszeile und kopiert sie.

[plantuml, target=laufzeit-zurueck, format=svg]
....
@startuml
autonumber
actor "Lernende" as kind
participant "claude.ai" as claude
participant "Layout\n(kompetenz.njk)" as seite
participant "Kern: Seitenstart\n(seite.js)" as start
participant "Kern: Trainer\n(ui.js)" as trainer
participant "Kern: Rückweg\n(zurueck.js)" as zurueck
participant "Zwischenablage\n(Gerät)" as clip
participant "Browser-Tab" as tab

claude -> kind : Link …/erste-binomische.html?nr=4&von=tutor
kind -> seite : öffnet ihn (neuer Tab, von claude.ai)
seite -> start : starteSeite({ app, modul, zeichne, kompetenz })
start -> trainer : starteTrainer({ seed: 4 })
start -> zurueck : vomTutor(query) → true
zurueck -> kind : Knopf "Zurück zu Claude" unter "Link kopieren"
kind -> trainer : tippt, "Prüfen" (1 falsch, 1 richtig)
trainer -> zurueck : nachVersuch(stand, korrekt)
kind -> zurueck : Klick "Zurück zu Claude"
zurueck -> trainer : stand() → Nummer, Status, Sitzung
zurueck -> clip : writeText("Binomische Formeln, Kompetenz 2 „Erste binomische Formel“,\nAufgabe Nr. 4: richtig im 2. Versuch (Sitzung: 1 von 2 richtig)")
alt Zwischenablage verweigert
  clip --> zurueck : Fehler
  zurueck -> kind : Feld mit markierter Zeile, Hinweis (aria-live);\nder Tab bleibt offen
else kopiert
  zurueck -> tab : nach 100 ms window.close()
  zurueck -> tab : nach 300 ms window.closed?
  alt Tab kam von claude.ai
    tab --> kind : Tab zu, claude.ai ist wieder vorn
  else Tab selbst geöffnet (Lesezeichen, eingetippt)
    tab --> zurueck : closed = false
    zurueck -> kind : "Ergebnis kopiert. Schließ diesen Tab\nund füge es bei Claude ein." (aria-live)
  end
end
kind -> claude : fügt die Zeile ein (im Rückfall selbst kopiert)
@enduml
....

Ohne `von=tutor` zeigt die Seite keinen Knopf, ohne JavaScript ebenfalls. „Link zu dieser Aufgabe“ und
„Link kopieren“ lassen den Parameter weg. Der Rückfall für mobile In-App-Browser ist ungetestet
(xref:11_technical_risks.adoc#r-021[R-021]).
